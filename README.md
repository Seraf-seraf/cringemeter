# Кринжометр

Telegram-бот для оценки видео: Кринж / Некринж, общие голоса и топ.

Бот предназначен для одной группы. По согласованному контракту видео и
видеокружки получают кнопки **«🤡Кринж»** и **«Некринж🙂‍↕️»** в столбик,
по одной кнопке в строке. Повторные
публикации одного `file_unique_id` используют общие голоса: один текущий выбор
пользователя на файл. `/top` показывает до 10 уникальных медиа с минимум
5 голосами. Бинарные видео и `file_id` не сохраняются.

Стек: Go, Telegram Bot API через webhook, Vercel Go Functions, Turso (libSQL).

`/api/webhook` принимает только POST с `X-Telegram-Bot-Api-Secret-Token`,
проверяет JSON, целевую группу и принадлежность callback собственной публикации.
Бот копирует видео с кнопками, сохраняет ID копии и затем удаляет оригинал.
Неоднозначный результат копирования сохраняется как `copy_unknown`: автоматической
повторной копии нет. После неудачного удаления повторная доставка повторяет только
удаление. Для ручного восстановления сначала нужно сверить публикации в Telegram
и строки `posts`; не сбрасывайте `copy_unknown` без проверки фактической копии.

Голоса сохраняются до обновления кнопок. Синхронизация ограничена 10 сообщениями
и 2 секундами; при 429 останавливается. Следующее голосование или повторная доставка
публикации повторяет синхронизацию. При большом числе копий часть кнопок может
оставаться устаревшей; `/top` всегда читает актуальные голоса из БД.

Для проверки требуется Go 1.22 или новее:

```sh
make test
make vet
```

Структура: `api/` — HTTP entry points; `internal/domain/` — бизнес-правила;
`internal/app/` — сценарии; `internal/adapters/` — внешние интеграции.

## Переменные окружения

Все переменные приложения перечислены в [`.env.example`](.env.example).

| Переменная | Обязательность / default | Назначение и допустимое значение |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | Обязательна для webhook; секрет | Токен нужного бота из [@BotFather](https://t.me/BotFather), формат `<положительный bot_id>:<токен>`. ID своего бота вычисляется из токена. |
| `TELEGRAM_WEBHOOK_SECRET` | Обязательна для webhook; секрет | Отдельный случайный секрет регистрации webhook: 1–256 символов `A-Z`, `a-z`, `0-9`, `_`, `-`. То же значение передаётся в `setWebhook.secret_token`. |
| `TELEGRAM_CHAT_ID` | Обязательна для webhook | Отрицательный числовой ID единственной группы, например `-1001234567890`; не username и не ссылка. |
| `TURSO_DATABASE_URL` | Обязательна для webhook, миграций и operations | URL БД из Turso или интеграции Vercel: `libsql://<host>` или `https://<host>`. Без credentials, query-параметров, fragment и пути, кроме `/`. |
| `TURSO_AUTH_TOKEN` | Обязательна для webhook, миграций и operations; секрет | Непустой токен доступа к этой БД с правом записи; для миграции также нужны права создания таблиц и индекса. |
| `TOP_LIMIT` | Необязательна; `10` | Максимальное число уникальных медиа в `/top`: целое число от 1 до 10. |
| `TOP_MIN_VOTES` | Необязательна; `5` | Минимум уникальных голосов для попадания в `/top`: целое число не меньше 5. |
| `CRINGEMETER_ADMIN_SECRET` | Обязательна только для `/api/operations`; секрет | Отдельный непустой секрет административных запросов в заголовке `X-Cringemeter-Admin-Secret`. Без него operations отклоняет все запросы; обычный webhook и локальная миграция от него не зависят. |

Пустые `TOP_LIMIT` и `TOP_MIN_VOTES` включают defaults. Некорректные настройки
webhook дают HTTP 503. Отдельные переменные для bot ID, username и webhook URL
не нужны: URL задаётся при регистрации webhook.

В Vercel добавьте переменные в **Project → Settings → Environment Variables**
для нужного environment. Токены и оба секрета храните как **Sensitive** для
Production/Preview. Изменения env применяются к новому deployment: после изменения
настроек нужен redeploy. Для Preview используйте отдельные тестовые бот, группу и
БД; не регистрируйте webhook production-бота на Preview.

Для локальной работы скопируйте `.env.example` в `.env` и заполните значения.
Приложение не загружает `.env` автоматически; передайте переменные через окружение
процесса. Например, для заполненного файла в формате shell:

```sh
set -a
. ./.env
set +a
go run ./cmd/migrate
```

Не сохраняйте настоящие токены в Git, логах или документации.

## Настройки Telegram-бота

1. В [@BotFather](https://t.me/BotFather) создайте или выберите бота. Его токен
   сохраните в `TELEGRAM_BOT_TOKEN`.
2. Разрешите добавление в группы: `/setjoingroups` → выбрать бота → **Enable**.
3. Добавьте бота в целевую группу как **администратора**, включите право
   **удаления сообщений** и возможность отправлять сообщения/медиа.
   ID этой группы запишите в `TELEGRAM_CHAT_ID`.
4. Для приёма обычных видео без команд и упоминаний бот должен получать все
   сообщения группы. Администратор получает их и при включённом Group Privacy.
   Можно также отключить его в BotFather: `/setprivacy` → выбрать бота →
   **Disable**. После изменения Privacy Telegram требует заново добавить бота
   в группу; затем проверьте права администратора и удаления.
5. Для видео, опубликованных другими ботами, включите в настройках своего бота
   в BotFather **Bot-to-Bot Communication Mode**. С правами администратора бот
   получает такие сообщения без отдельного упоминания или ответа.
6. Необязательно: через `/setcommands` добавьте команду меню:

   ```text
   top - Рейтинг кринжовых видео
   ```

Регистрация команды в меню не обязательна для обработки `/top` и
`/top@username_бота`. Собственные сообщения бот игнорирует; документы MP4 и GIF
не обрабатываются.

Спецификация Telegram: [Privacy Mode](https://core.telegram.org/bots/features#privacy-mode)
и [Bot-to-Bot Communication](https://core.telegram.org/bots/features#bot-to-bot-communication).

## Миграции и webhook

Миграции выполняются явно, вне webhook. С локальными переменными Turso:

```sh
go run ./cmd/migrate
```

При недоступности интеграционных секретов локально используется POST
`/api/operations` с отдельным `X-Cringemeter-Admin-Secret` и JSON
`{"action":"probe"}`, `{"action":"migrate"}` или `{"action":"check"}`.
Для этого задайте `CRINGEMETER_ADMIN_SECRET`. Endpoint не принимает SQL и
не возвращает пользовательские данные или секреты. `probe` также сообщает,
включены ли внешние ключи (`foreign_keys_enabled`). Миграция создаёт три таблицы
и индекс, затем проверяет их определения; повторный запуск проверяет схему. Запись
`PRAGMA user_version` не используется: целевая Turso её запрещает.

Deployment выполняется через Vercel MCP из конкретного commit в `main`.
Сначала проверяются Preview, подключение и тесты, затем Production, миграция
и HTTP-контракт. Production webhook должен быть доступен без Vercel SSO;
Preview остаётся защищённым. По возможности используйте отдельные тестовые
бот и БД; не отправляйте фиктивные видео или голоса в общую production БД.
После deployment и миграции зарегистрируйте webhook через Telegram Bot API
[`setWebhook`](https://core.telegram.org/bots/api#setwebhook):

| Параметр Bot API | Настройка |
| --- | --- |
| `url` | Публичный HTTPS URL production-функции: `https://<production-domain>/api/webhook`. В текущем запуске — `https://cringemeter-pi.vercel.app/api/webhook`. |
| `secret_token` | Точное значение `TELEGRAM_WEBHOOK_SECRET` из этого deployment. |
| `allowed_updates` | `["message", "callback_query"]`. |
| `max_connections` | В текущем запуске — `2`. |
| `ip_address` | Необязателен. При сбое DNS Telegram можно указать проверенный текущий IP deployment. В текущем запуске задан `216.198.79.3`; перед новой регистрацией сверяйте адрес с DNS production-домена. |

Это параметры регистрации Bot API, а не дополнительные env-переменные.
Production URL должен отвечать Telegram без Vercel SSO или страницы входа;
секретный заголовок проверяет само приложение. После смены webhook secret
нужны новый deployment и повторный `setWebhook` с тем же новым секретом.
После регистрации проверяйте [`getWebhookInfo`](https://core.telegram.org/bots/api#getwebhookinfo):
правильные `url` и `allowed_updates`, отсутствие новых ошибок доставки и
снижение `pending_update_count` до нуля. Таймаут обработки webhook — 8 секунд,
функции — 10 секунд.

Приёмка в группе: видео, кружок, пересылка, повтор того же файла, смена голоса
на разных копиях, `/top` с 4 и 5 уникальными голосами, игнорирование чужой группы
и собственных сообщений. Общий ключ — `file_unique_id`, а не хеш изображения:
перекодированное видео может получить другой набор голосов.

Перед каждым этапом обязательны актуальные
[канонические инструкции](https://github.com/Seraf-seraf/AGENTS.md/blob/main/AGENTS.md)
и релевантные skills этого репозитория.
