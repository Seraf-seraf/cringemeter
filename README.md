# Кринжометр

Telegram-бот для оценки видео: Кринж / Некринж и рейтинг «Короли кринжа».

Бот предназначен для одной группы. По согласованному контракту видео и
видеокружки получают кнопки **«🤡Кринж»** и **«🙂‍↕️Некринж»** в столбик,
по одной кнопке в строке. Повторные
публикации одного `file_unique_id` **одним автором** используют общие голоса:
один текущий выбор голосующего на файл и автора. У разных авторов голоса
одинакового файла раздельные: голос начисляется отправителю копии, под которой
нажали кнопку. Пересланное видео засчитывается тому, кто отправил его в группу.

`/top` показывает **трёх пользователей** с наибольшим положительным балансом
**Кринж − Некринж** по всем их видео и кружочкам. Например, 100 голосов «Кринж»
и 30 «Некринж» дают 70 баллов. Один «Кринж» добавляет 1, один «Некринж»
вычитает 1; смена «Кринж» на «Некринж» уменьшает баланс на 2.
Отрицательные баллы одного видео учитываются в общей сумме автора.
Повторы одного файла автором не умножают результат. При равенстве выше тот,
кто раньше достиг **текущего** счёта: потеря и возврат голоса обновляют порядок.
Повторное нажатие той же кнопки и повторная публикация не меняют место.
Пользователи с нулевым или отрицательным счётом не выводятся.
Анонимные сообщения без личного отправителя и боты не участвуют в топе.

Третья кнопка показывает **«👤 Автор: @username»** (имя или ID, если username
нет; «не определён», если автор неизвестен). Только текущие администраторы
группы могут открыть список известных боту участников и выбрать автора.
Список разбит на страницы по 10 человек: навигация «← · 1/10 · →»
показывает текущую и общее число страниц. Стрелки на краях остаются
на текущей странице.
Telegram Bot API не возвращает полный состав группы: участник, который
ещё не писал и не голосовал, может отсутствовать в списке.
Нажатие обычного участника тихо закрывает индикатор ожидания, ничего не меняя.
Бот запоминает людей из сообщений и голосований; перед назначением проверяет,
что выбранный человек ещё состоит в группе и не является ботом.

Один логический пост — пара **`(file_unique_id, user_id)`**. Смена автора
переносит общий набор голосов и все Telegram-копии этой пары новому владельцу,
атомарно пересчитывая топ. Если такая новая пара уже существует, наборы
объединяются: один текущий голос человека, более поздний `updated_at` побеждает;
при равной дате сохраняется голос существующей целевой пары. Голос нового
автора за этот ролик исключается как самоголос. Устаревший выбор админа
отклоняется, изменения сохраняются в журнале. При неизменном итоговом счёте
пользователя сохраняется его порядок при равенстве баллов.

Ссылки на YouTube от пользователей сохраняются в очереди БД с автором,
ID сообщения и YouTube ID. Видео от настроенного загрузчика связывается
с конкретным ответом на ссылку либо с совпавшим YouTube ID из подписи,
URL кнопки или имени файла вида `<youtube_id>.mp4`.
Если идентификаторов нет, применяется согласованный **FIFO**: первый
обрабатываемый ролик получает автора первой ожидающей ссылки в этой группе.
Для FIFO история содержит `evidence=fifo`, `verified=false`: порядок не
доказывает совпадение видео. Явное несовпадение ID или неоднозначные метаданные
оставляют видео без автора; такие ролики получают кнопки, но не входят в топ.
При успешной публикации и удалении исходного ролика запрос уходит из очереди,
а история сопоставления остаётся. Повтор webhook не забирает следующий запрос.
Резервирование запроса и запись автора атомарны; при ошибке публикации запрос
остаётся закреплённым за своим роликом. Уже обработанные ссылки не возвращаются
в очередь при повторной доставке. Старые записи загрузчика не переатрибутируются.

[massbots API](https://api.massbots.xyz/docs) получает данные и загружает видео
по YouTube ID; в опубликованной OpenAPI 1.7.24 нет обратного поиска YouTube ID
по Telegram-файлу или чтения истории чужого загрузчика. Этот API не подключён:
нужен отдельный ключ `X-Token`. Telegram `file_unique_id` обозначает файл,
но сам по себе не подтверждает исходную YouTube-ссылку.

Самоголоса запрещены на обеих кнопках, в том числе под повторными копиями
своего видео. Telegram показывает popup **«Нельзя голосовать за своё видео»**,
голос не записывается и счётчики не меняются. Если такой же файл отправил другой
человек, голосовать под его копией можно. Запрет применяется к отправителю
конкретной копии, в том числе пересланного видео. Сохранённые ранее самоголоса
не участвуют в счётчиках и рейтинге; их физическое удаление — отдельная
административная операция, не миграция.

Голос и порядок достижения счёта фиксируются атомарно в БД; параллельные
запросы не теряют голоса. Бинарные видео и `file_id` не сохраняются.

Стек: Go, Telegram Bot API через webhook, Vercel Go Functions, Turso (libSQL).

`/api/webhook` принимает только POST с `X-Telegram-Bot-Api-Secret-Token`,
проверяет JSON, целевую группу и принадлежность callback собственной публикации.
Бот копирует видео с кнопками, сохраняет ID копии и затем удаляет оригинал.
Неоднозначный результат копирования сохраняется как `copy_unknown`: автоматической
повторной копии нет. После неудачного удаления повторная доставка повторяет только
удаление. Для ручного восстановления сначала нужно сверить публикации в Telegram
и строки `posts`; не сбрасывайте `copy_unknown` без проверки фактической копии.

Голоса сохраняются до обновления кнопок. Синхронизация ограничена 10 сообщениями
и 2 секундами; при 429 останавливается. Следующее голосование или повторная доставка
публикации повторяет синхронизацию. При большом числе копий часть кнопок может
оставаться устаревшей; `/top` всегда читает актуальные голоса из БД.

Для проверки требуется Go 1.22 или новее:

```sh
make test
make vet
```

Структура: `api/` — HTTP entry points; `internal/domain/` — бизнес-правила;
`internal/app/` — сценарии; `internal/adapters/` — внешние интеграции.

## Переменные окружения

Все переменные приложения перечислены в [`.env.example`](.env.example).

| Переменная | Обязательность / default | Назначение и допустимое значение |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | Обязательна для webhook; секрет | Токен нужного бота из [@BotFather](https://t.me/BotFather), формат `<положительный bot_id>:<токен>`. ID своего бота вычисляется из токена. |
| `TELEGRAM_WEBHOOK_SECRET` | Обязательна для webhook; секрет | Отдельный случайный секрет регистрации webhook: 1–256 символов `A-Z`, `a-z`, `0-9`, `_`, `-`. То же значение передаётся в `setWebhook.secret_token`. |
| `TELEGRAM_CHAT_ID` | Обязательна для webhook | Отрицательный числовой ID единственной группы, например `-1001234567890`; не username и не ссылка. |
| `TURSO_DATABASE_URL` | Обязательна для webhook, миграций и operations | URL БД из Turso или интеграции Vercel: `libsql://<host>` или `https://<host>`. Без credentials, query-параметров, fragment и пути, кроме `/`. |
| `TURSO_AUTH_TOKEN` | Обязательна для webhook, миграций и operations; секрет | Непустой токен доступа к этой БД с правом записи; для миграции также нужны права создания таблиц, индекса, view и триггеров. |
| `CRINGEMETER_ADMIN_SECRET` | Обязательна только для `/api/operations`; секрет | Отдельный непустой секрет административных запросов в заголовке `X-Cringemeter-Admin-Secret`. Без него operations отклоняет все запросы; обычный webhook и локальная миграция от него не зависят. |
| `TELEGRAM_DOWNLOADER_BOT_ID` | Необязательна; без неё привязка загрузчика выключена | Положительный числовой ID доверенного загрузчика. Для @TTPapaBot: `2083515400`. FIFO и проверка ссылок применяются только к его видео. Для Preview настройте тестового загрузчика отдельно. |
| `TELEGRAM_DEBUG_UPLOADS` | Необязательна; по умолчанию выключена | Значение `1` включает диагностический лог видео, YouTube-ссылок и сообщений других ботов только из заданной группы. Лог содержит ID сообщений и отправителей, username, признаки reply/forward/via_bot, guest caller (новое поле Bot API), тип медиа, наличие имени файла и кнопок, ID YouTube-видео и упомянутых пользователей; тексты, подписи, полные URL и секреты не выводятся. Для выключения удалите значение и сделайте redeploy. |

Топ фиксирован: три пользователя, без минимального порога в пять голосов.
Старые `TOP_LIMIT` и `TOP_MIN_VOTES` больше не читаются. Некорректные настройки
webhook дают HTTP 503. Отдельные переменные для bot ID, username и webhook URL
не нужны: URL задаётся при регистрации webhook.

В Vercel добавьте переменные в **Project → Settings → Environment Variables**
для нужного environment. Токены и оба секрета храните как **Sensitive** для
Production/Preview. Изменения env применяются к новому deployment: после изменения
настроек нужен redeploy. Для Preview используйте отдельные тестовые бот, группу и
БД; не регистрируйте webhook production-бота на Preview.

Для локальной работы скопируйте `.env.example` в `.env` и заполните значения.
Приложение не загружает `.env` автоматически; передайте переменные через окружение
процесса. Например, для заполненного файла в формате shell:

```sh
set -a
. ./.env
set +a
go run ./cmd/migrate
```

Не сохраняйте настоящие токены в Git, логах или документации.

## Настройки Telegram-бота

1. В [@BotFather](https://t.me/BotFather) создайте или выберите бота. Его токен
   сохраните в `TELEGRAM_BOT_TOKEN`.
2. Разрешите добавление в группы: `/setjoingroups` → выбрать бота → **Enable**.
3. Добавьте бота в целевую группу как **администратора**, включите право
   **удаления сообщений** и возможность отправлять сообщения/медиа.
   ID этой группы запишите в `TELEGRAM_CHAT_ID`.
4. Для приёма обычных видео без команд и упоминаний бот должен получать все
   сообщения группы. Администратор получает их и при включённом Group Privacy.
   Можно также отключить его в BotFather: `/setprivacy` → выбрать бота →
   **Disable**. После изменения Privacy Telegram требует заново добавить бота
   в группу; затем проверьте права администратора и удаления.
5. Для видео, опубликованных другими ботами, включите в настройках своего бота
   в BotFather **Bot-to-Bot Communication Mode**. С правами администратора бот
   получает такие сообщения без отдельного упоминания или ответа.
6. Необязательно: через `/setcommands` добавьте команду меню:

   ```text
   top - Короли кринжа
   ```

Регистрация команды в меню не обязательна для обработки `/top` и
`/top@username_бота`. Собственные сообщения бот игнорирует; документы MP4 и GIF
не обрабатываются.

Спецификация Telegram: [Privacy Mode](https://core.telegram.org/bots/features#privacy-mode)
и [Bot-to-Bot Communication](https://core.telegram.org/bots/features#bot-to-bot-communication).

## Миграции и webhook

Миграции выполняются явно, вне webhook. С локальными переменными Turso:

```sh
go run ./cmd/migrate
```

При недоступности интеграционных секретов локально используется POST
`/api/operations` с отдельным `X-Cringemeter-Admin-Secret` и JSON
`{"action":"probe"}`, `{"action":"migrate"}` или `{"action":"check"}`.
Для отдельного ручного удаления только самоголосов после обновления схемы:
`{"action":"remove_self_votes"}`. Операция выполняет фиксированный
`DELETE FROM author_votes WHERE user_id=uploader_user_id` и возвращает число
удалённых строк `removed`; повторный запуск безопасен.
Для этого задайте `CRINGEMETER_ADMIN_SECRET`. Endpoint не принимает SQL и
не возвращает секреты или содержимое сообщений. Для диагностики отправителя
доступна read-only команда `{"action":"diagnose_uploads"}`: последние 20 записей
только из `TELEGRAM_CHAT_ID`, с ID автора/сообщений, состоянием и числом голосов,
а также источником сопоставления, ожидаемым/полученным YouTube ID,
признаком `verified` и первыми 20 запросами очереди.
Миграция `005_author_management.sql` добавляет список известных участников
и журнал смены автора, сохраняя существующие голоса, очередь и порядок топа.
Миграция `004_download_requests.sql` добавляет очередь, историю и реестр ботов,
сохраняя голоса и порядок топа. После миграции действие
`{"action":"register_downloader"}` регистрирует **только** ID из
`TELEGRAM_DOWNLOADER_BOT_ID`, исключая старые публикации загрузчика из топа
без удаления голосов. Произвольный ID через endpoint передать нельзя.
Без корректного ID группы этот отчёт недоступен. `probe` также сообщает,
включены ли внешние ключи (`foreign_keys_enabled`). Миграции создают исходные `media`, `posts`, `votes` и индекс, затем
`author_votes`, `score_positions`, view `user_scores` и триггеры.
Миграция `003_net_scores.sql` разрешает отрицательный внутренний счёт,
пересчитывает баланс из сохранённых голосов и добавляет запрет самоголоса
на уровне БД. Она **не удаляет голоса**. Пересчёт и изменение схемы проходят
в одной транзакции; повторный запуск сохраняет данные и порядок.
Начальные ничьи после смены формулы сохраняют ранее установленный порядок:
история достижения нового баланса до обновления не восстанавливается.
Последующие изменения баланса получают строго упорядоченный номер в БД.

Исходные общие голоса `votes` уже были обнулены при прежнем переходе на рейтинг
авторов по запросу пользователя. Таблица оставлена для чтения запросами старого
deployment; текущие голоса находятся в `author_votes`. Записи в старую таблицу
запрещены. Старый callback, получивший HTTP 503 при обновлении, повторяется
Telegram на новом deployment. Запись `PRAGMA user_version` не используется:
целевая Turso её запрещает.

Deployment выполняется через Vercel MCP из конкретного commit в `main`.
Сначала проверяются Preview, подключение и тесты, затем Production, миграция
и HTTP-контракт. Production webhook должен быть доступен без Vercel SSO;
Preview остаётся защищённым. По возможности используйте отдельные тестовые
бот и БД; не отправляйте фиктивные видео или голоса в общую production БД.
После deployment и миграции зарегистрируйте webhook через Telegram Bot API
[`setWebhook`](https://core.telegram.org/bots/api#setwebhook):

| Параметр Bot API | Настройка |
| --- | --- |
| `url` | Публичный HTTPS URL production-функции: `https://<production-domain>/api/webhook`. В текущем запуске — `https://cringemeter-pi.vercel.app/api/webhook`. |
| `secret_token` | Точное значение `TELEGRAM_WEBHOOK_SECRET` из этого deployment. |
| `allowed_updates` | `["message", "callback_query"]`. |
| `max_connections` | В текущем запуске — `2`. |
| `ip_address` | Необязателен. При сбое DNS Telegram можно указать проверенный текущий IP deployment. В текущем запуске задан `216.198.79.3`; перед новой регистрацией сверяйте адрес с DNS production-домена. |

Это параметры регистрации Bot API, а не дополнительные env-переменные.
Production URL должен отвечать Telegram без Vercel SSO или страницы входа;
секретный заголовок проверяет само приложение. После смены webhook secret
нужны новый deployment и повторный `setWebhook` с тем же новым секретом.
После регистрации проверяйте [`getWebhookInfo`](https://core.telegram.org/bots/api#getwebhookinfo):
правильные `url` и `allowed_updates`, отсутствие новых ошибок доставки и
снижение `pending_update_count` до нуля. Таймаут обработки webhook — 8 секунд,
функции — 10 секунд.

Приёмка в группе: видео, кружок, пересылка, повтор того же файла, смена голоса
на копиях одного автора и разных авторов, `/top` с одним голосом, суммой
нескольких видео, тремя лидерами и равным счётом после потери/возврата голоса,
балансом Кринж − Некринж, исключением нулевых и отрицательных результатов,
popup при попытке самоголоса,
игнорирование чужой группы
и собственных сообщений. Общий ключ — `file_unique_id`, а не хеш изображения:
перекодированное видео может получить другой набор голосов.

Перед каждым этапом обязательны актуальные
[канонические инструкции](https://github.com/Seraf-seraf/AGENTS.md/blob/main/AGENTS.md)
и релевантные skills этого репозитория.
