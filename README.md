# Кринжометр

Telegram-бот для оценки видео: Кринж / Некринж, общие голоса и топ.

Бот предназначен для одной группы. По согласованному контракту видео и
видеокружки получают кнопки **«🤡Кринж»** и **«Некринж🙂‍↕️»**. Повторные
публикации одного `file_unique_id` используют общие голоса: один текущий выбор
пользователя на файл. `/top` показывает до 10 уникальных медиа с минимум
5 голосами. Бинарные видео и `file_id` не сохраняются.

Стек: Go, Telegram Bot API через webhook, Vercel Go Functions, Turso (libSQL).

`/api/webhook` принимает только POST с `X-Telegram-Bot-Api-Secret-Token`,
проверяет JSON, целевую группу и принадлежность callback собственной публикации.
Бот копирует видео с кнопками, сохраняет ID копии и затем удаляет оригинал.
Неоднозначный результат копирования сохраняется как `copy_unknown`: автоматической
повторной копии нет. После неудачного удаления повторная доставка повторяет только
удаление. Для ручного восстановления сначала нужно сверить публикации в Telegram
и строки `posts`; не сбрасывайте `copy_unknown` без проверки фактической копии.

Голоса сохраняются до обновления кнопок. Синхронизация ограничена 10 сообщениями
и 2 секундами; при 429 останавливается. Следующее голосование или повторная доставка
публикации повторяет синхронизацию. При большом числе копий часть кнопок может
оставаться устаревшей; `/top` всегда читает актуальные голоса из БД.

Для проверки требуется Go 1.22 или новее:

```sh
make test
make vet
```

Структура: `api/` — HTTP entry points; `internal/domain/` — бизнес-правила;
`internal/app/` — сценарии; `internal/adapters/` — внешние интеграции.

В `.env.example` перечислены настройки. Первые пять переменных
обязательны; `TOP_LIMIT` и `TOP_MIN_VOTES` имеют значения по умолчанию 10 и 5.
`TELEGRAM_WEBHOOK_SECRET` должен содержать от 1 до 256 символов `A-Z`, `a-z`,
`0-9`, `_`, `-`. Настройки проверяются при вызове handler; `.env` автоматически
не загружается. Не сохраняйте настоящие токены в Git, логах или документации.

Бот должен быть администратором целевой группы с правом удаления сообщений.
В BotFather отключите Group Privacy (`/setprivacy` → Disable); для сообщений
других ботов включите Bot-to-Bot Communication Mode, если эта настройка доступна.
Собственные сообщения бот игнорирует. Документы MP4 и GIF не обрабатываются.

Миграции выполняются явно, вне webhook. С локальными переменными Turso:

```sh
go run ./cmd/migrate
```

При недоступности интеграционных секретов локально используется POST
`/api/operations` с отдельным `X-Cringemeter-Admin-Secret` и JSON
`{"action":"probe"}`, `{"action":"migrate"}` или `{"action":"check"}`.
Для этого задайте `CRINGEMETER_ADMIN_SECRET`. Endpoint не принимает SQL и
не возвращает данные или секреты. Миграция создаёт три таблицы и устанавливает
проверяет их определения; повторный запуск проверяет схему. Запись
`PRAGMA user_version` не используется: целевая Turso её запрещает.

Deployment выполняется через Vercel MCP из конкретного commit в `main`.
Сначала проверяются Preview, подключение и тесты, затем Production, миграция
и HTTP-контракт. Production webhook должен быть доступен без Vercel SSO;
Preview остаётся защищённым. По возможности используйте отдельные тестовые
бот и БД; не отправляйте фиктивные видео или голоса в общую production БД.
В Telegram `setWebhook` задаются HTTPS URL `/api/webhook`, `secret_token`
и `allowed_updates=["message","callback_query"]`. Проверяйте `getWebhookInfo`
после регистрации. Таймаут обработки webhook — 8 секунд, функции — 10 секунд.

Приёмка в группе: видео, кружок, пересылка, повтор того же файла, смена голоса
на разных копиях, `/top` с 4 и 5 уникальными голосами, игнорирование чужой группы
и собственных сообщений. Общий ключ — `file_unique_id`, а не хеш изображения:
перекодированное видео может получить другой набор голосов.

Перед каждым этапом обязательны актуальные
[канонические инструкции](https://github.com/Seraf-seraf/AGENTS.md/blob/main/AGENTS.md)
и релевантные skills этого репозитория.
